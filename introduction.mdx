City Metro Trip Planner is a fully deployed, production web application for the City Metro transit network. It gives riders an interactive canvas map of the entire network, real-time vehicle positions, step-by-step multi-leg journey planning, and the ability to save trips to their account — all from a mobile-first UI that ships as a zero-dependency static site on Cloudflare Workers.

<Note>
  The live backend API at `https://api.trip-planner.citymetro.xyz` is operated by City Metro. It is not publicly writable — read-only endpoints (`/api/network`, `/api/plan`, `/api/live`) are open to any client, but journey-saving and account features require a Bearer token issued by City Metro's Authentik identity provider at `https://auth.citymetro.xyz`.
</Note>

## The two main pages

The app is two HTML pages served from the `pages/` directory:

| Page | URL | Purpose |
|---|---|---|
| `pages/index.html` | `/` | Live canvas map, nearby services, station arrivals |
| `pages/planner.html` | `/planner` | Origin-to-destination trip planner with route modes |

`index.html` boots `js/map-page.js` as an ES module. `planner.html` boots `js/planner-page.js`. Both pages share the same `css/app.css` stylesheet and pull all data from the single API base.

## API base

Every network request is rooted at one constant defined in `js/config.js`:

```js
export const API_BASE = 'https://api.trip-planner.citymetro.xyz';
```

All JavaScript modules import `API_BASE` from `config.js` — it is the only place the server address lives.

## Tech stack

City Metro Trip Planner is built entirely from standard web platform primitives:

- **Vanilla ES modules** — no bundler, no framework, no build step. The browser loads each `.js` file directly.
- **HTML Canvas** — the transit map and route visualisation are drawn on a `<canvas>` element, not a third-party map library.
- **Cloudflare Workers static assets** — `wrangler deploy` publishes the `pages/` directory as a Workers static site. There is no server-side rendering.

## Authentication and the `api()` wrapper

Authentication state is managed entirely in `localStorage` through the `Auth` object exported from `js/api.js`:

```js
export const Auth = {
  token: () => localStorage.getItem('cm_token'),
  user() { try { return JSON.parse(localStorage.getItem('cm_user')); } catch { return null; } },
  set(token, user) { localStorage.setItem('cm_token', token); localStorage.setItem('cm_user', JSON.stringify(user)); },
  clear() { localStorage.removeItem('cm_token'); localStorage.removeItem('cm_user'); },
  login(returnTo = location.pathname + location.search) {
    location.href = `${API_BASE}/api/auth/login?site=${encodeURIComponent(location.origin)}&return=${encodeURIComponent(returnTo)}`;
  },
  get loggedIn() { return !!this.token(); }
};
```

`Auth.login()` starts an OAuth flow through `API_BASE + /api/auth/login`, which redirects back to `/auth-callback.html` after a successful sign-in. `Auth.clear()` is called automatically when the API returns a `401` on an already-authenticated request (expired session).

Every network call goes through the `api()` wrapper, which attaches the Bearer token when present, throws a human-readable error on failure, and deserialises JSON automatically:

```js
export async function api(path, opts = {}) {
  const headers = { 'Content-Type': 'application/json', ...opts.headers };
  if (Auth.token()) headers.Authorization = `Bearer ${Auth.token()}`;
  let res;
  try { res = await fetch(API_BASE + path, { ...opts, headers }); }
  catch { throw new Error('Cannot reach the City Metro server'); }
  const data = await res.json().catch(() => ({}));
  if (res.status === 401 && Auth.loggedIn && !path.startsWith('/api/auth')) Auth.clear();
  if (!res.ok) throw new Error(data.error || `Request failed (${res.status})`);
  return data;
}
```
